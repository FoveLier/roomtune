# 期末项目 intent：声居 RoomTune · 数字房间声学校正系统

- Author: 李熹元·20241010113
- Date: 2026-11-11
- Status: **approved**
- 选题方向：生活服务（家庭影音/居住体验） | 来源：自选题（非菜单题）
- 自评难度：★★★（AI 解释层 + 2D 房间编辑器 + 图表/确定性声学规则引擎）

## 问题

很多家庭把音箱搬进客厅或书房后，只能靠耳朵反复挪位置；房间尺寸、形状、墙角、玻璃/瓷砖/地毯、沙发和柜体会让低频驻波、SBIR 与早期反射叠加，出现低频轰头、某个座位低音特别强、声像偏移、对白模糊。专业声学校正通常依赖 Dirac Live、Audyssey、REW + UMIK-1 等工具和测量经验，普通用户不知道该量什么、先改摆位还是先买吸音板，也读不懂频响、瀑布图和相位曲线。自动校准通常绑定 AVR/处理器，按固定目标曲线和多点平均工作，能修一部分峰谷，却不会告诉用户“先挪哪只音箱、低音炮放哪、墙上贴什么、装修前能做到什么程度”，也很难兼顾深谷、相位和多座位差异。于是用户要么花很多钱买设备，要么在没处理的房间里继续忍受“低音轰、声像糊”的体验。

## 预期成果

1. **核心** PC 端新建房间项目：输入长宽高、形状、门窗、墙地顶材质、家具和听音位，看到房间俯视图、预估驻波、Schroeder 频率、RT60 区间与红/黄/绿风险标记。
2. **核心** PC 端在 2D 房间图上拖拽主音箱、低音炮和听音位，选择音箱型号/数量/类型（2.0、2.1、5.1、5.1.2、7.1.4），输入低频下潜、高频延伸、灵敏度、最大声压与听音动态范围，实时看到距离、夹角、toe-in、离墙/离角距离、第一反射点预警与 EQ headroom。
3. **核心** PC 端生成 2–3 套“先免费、后装修”的摆位方案，按低频、声像、动线、施工难度对比，并解释取舍。
4. PC 端低音炮方案：根据房间模式和座位输入 1–4 只低音炮，看到候选位置、相位/延迟/增益调整步骤，以及单炮与多炮的预期差异。
5. PC 端声学装修清单：按优先级列出吸音/扩散/低频陷阱的位置、面积、厚度/频率范围、预算档位和替代软装（窗帘、地毯、书架），显示它主要改善哪些频段。
6. **核心** PC 端测量页导入 REW CSV/UMIK-1 结果，看到频响、脉冲/瀑布图、RT60 和多座位差异；没有测量时对应页面明确标注“估算”。
7. **核心** PC 端生成声学报告：中文的“先做什么、为什么、预期变化、风险”；数值由确定性规则引擎先计算，AI 只做解释；无 API Key 时使用本地报告。
8. **核心** PC 端参数卡：可抄入 AVR/Dirac/Audyssey/REW 的分频、距离/延迟、增益、低音炮相位、目标曲线和 PEQ 候选，结合动态范围标注 EQ 可提升余量、哪些必须实测。
9. 保存“现状 / 免费摆位 / 装修后”三个方案，在对比页看到频响、座位差异、预算与施工难度差异，并导出一张分享长图。
10. **核心** 手机端独立使用：项目列表、房间/音箱表单、声学分析、摆位/装修/参数卡；PC 端通过同步码与手机端双向导入导出。
11. PC/手机端都提供简洁清晰的浅色工作台界面，不使用复杂装饰和动效；手机端打包为 Android APK，PC 端打包为可运行桌面程序。

## 受影响的用户与系统

- 给谁用：家庭影院/HiFi 入门用户；租房或客厅不能大改造的人；影音店/声学顾问作为辅助工具。
- 跑在哪端：Windows PC（Visual Studio 2022 + WPF + .NET Framework 4.8）；Android 手机（HBuilderX + uni-app Vue3，APK）。PC 与手机均可独立使用，通过同步码配合。
- 用到什么：用户真实房间尺寸/材质/音箱型号/数量/类型/频响/灵敏度/最大声压/听音动态范围/摆位/听音偏好；REW CSV/UMIK-1 测量；PC 端本地 JSON、手机端本地 Storage；可选 LLM API（用户自填 Key）。
- 不做：微信小程序、web-view、支付、手机号验证、实时音频 DSP、直接控制 AVR/Dirac。
- 系统边界：输出可执行建议与参数卡，由用户现有设备/软件执行；精确校准以 UMIK-1 + REW 实测为准。

## 约束（自检清单）

- [x] 能力边界：不含支付 / web-view / 手机号验证
- [x] 真实数据源：用户真实房间尺寸/材质/音箱/听音位 + REW CSV/UMIK-1 测量；非 mock
- [x] 数据持久化：PC 本地 JSON（`F:\RoomTuneData`）；手机本地 Storage；同步码跨端
- [x] 中等复杂度交互：2D 房间编辑器、图表（模态/频响/RT60）、AI 解释层
- [x] 非红线题面：不是纯表单 CRUD / 纯待办清单 / 纯游戏 / 纯天气查看类，而是声学诊断与决策工具
- [x] 技术：PC 使用 Visual Studio 2022 + WPF + .NET Framework 4.8；手机使用 HBuilderX + uni-app Vue3，输出 Android APK

## 数据来源与 API 清单

- 房间、音箱、听音位、材质与偏好：用户实测输入；常见音箱/材料参数放本地离线库，免费。
- 测量：REW CSV / UMIK-1（REW 免费，UMIK-1 自备硬件）；手机端可通过同步码接收 PC 测量摘要，不冒充精确测量。
- LLM：PC 端可选 OpenAI-compatible API（DeepSeek/智谱等）；按 token 计费，单次报告约几千 token；用户自填 Key，保存于本机配置，不写入源码；无 Key 时本地规则报告。
- 无后端、无 uniCloud、无音乐/地图/蓝牙/ESP32 依赖。

## 已决问题与交付边界

- 精确/估算双轨：没有测量数据时明确“估算”；有 REW CSV/UMIK-1 时才输出“可抄参数”，并标注仍需复核。
- 只修宽峰、不拉平深谷；最大 boost 受 headroom 限制，优先摆位/声装。
- 目标曲线提供平直/Harman/电影三种模板；不把“拉平”当唯一正确答案。
- PC 与手机通过 Base64 JSON 同步码配合；不依赖网络同步。
- PC 端使用自绘 WPF 图表；手机端使用原生 CSS/Canvas 图表；不引入额外图表库。
